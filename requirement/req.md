# Role: 资深 AI 架构师 & 系统工程师
# Task: 构建 Vibe Investment 多智能体分析引擎 (Phase 1)

## 1. 系统愿景与边界 (System Overview)
实现一个超级AI Agent投资建议伙伴。人类负责给出一个“直觉（Vibe）”，然后由Agent进行发散-收敛-迭代，放大并细化人类的投资直觉。

你要实现一个基于 `langgraph` 的有向循环图（FSM），核心目的是验证多维正交视角的**发散（Divergence）**与**收敛（Convergence）**机制。

系统必须实现基于负反馈的自我循环以及状态的动态变异（Vibe Mutation）。

用户界面方面，实现一个CLI窗口交互器，方便用户使用。

由于现在是Phase 1，不考虑互联网搜索功能，无数据库持久化，只考虑单轮对话，但是必须保留拓展性。

## 2. 状态机拓扑 (FSM Topology)
系统由以下核心节点和路由逻辑组成：

1. **Planner (规划器)**：控制阀。负责评估信息充分度、更新动态 Vibe 并控制工作流的升降级。
   
   每一轮工作开始，Planner 结合 Talent 的涌现信息，对现有信息池进行“充分度评估/打分”。评估基于固定的规则卡片（`Skill`，默认为空，允许 Agent 根据当前阶段自由发挥）：
   * **信息充分**：提取结论，推进至下一阶段工作流。
   * **信息不充分且未达最大轮数**：将 Talent 的最新总结合并入原始 Vibe，生成 `Vibe_Next`，发起新一轮发散。
   * **信息不充分且达到最大轮数**：直接阻断并返回失败状态，输出当前的结论与矛盾点，要求人类提供更有方向性的 Vibe。
   
   工作流分类（依次递进）：
   * 价值发现（最大5轮，可配置）：扫描专家列表，选取3～6个专家进行宽口径分析。
   * 标的锁定（最大2轮，可配置）：选取2～4个专家，将抽象逻辑具象化为具体标的（如股票代码、Token、产业链节点）。
   * 逻辑验证（最大1轮，可配置）：选取1～3个专家，针对锁定的标的进行严谨的财务/筹码/链上数据逻辑推导。

2. **Expert_Swarm (专家集群 - 扇出/并发)**：系统动力的核心。10 个具有完全独立视角（独立上下文）的专家节点并发执行。
   
   * **状态保留**：保留专家完整的思考过程（如 `<think>` 内容）挂载在全局状态中，供需要时溯源。
   * **强制输出**：对外必须输出固定格式的“逻辑链条”、“精简结论”以及**“核心风险点”**。
   * *预设十个维度*：1.宏观冲浪者 2.技术布道者 3.成长股狂热者 4.资金博弈操盘手 5.深度价值卫道士 6.黑天鹅预言家 7.合规审查官 8.商业模式解构师 9.行为金融学家 10.第二层思维者。
   
3. **Talent(天才 - 涌现与收敛)**：擅长高维空间模式迁移。对专家意见进行交叉比对，为 Planner 提供决策依据。Talent 会根据当前工作流动态调整分析侧重点：
   
   * 价值发现：作为“战略家”，提取核心矛盾，涌现新的投资视角和待验证假设。
   * 标的锁定：作为“选股手”，评估专家提出的标的是否符合初始 Vibe 的审美，若偏离则标注异常。
   * 逻辑验证：作为“量化审计”，交叉比对专家的数据逻辑链是否闭环，指出推导过程中的致命漏洞。

## 3. 核心行为用例 (Behavior-Driven Case)
以下案例非真实，仅展示一个完整的端到端决策链条。

**用户输入 (Vibe_0)**: `"看好脑机接口 (BCI)，Neural-Link (NLK) 宣称突破双向读写，但无 FDA 审批，感觉有巨大预期差。"`

**期望的系统动态流转 (Mock 逻辑规范)**:

* **[阶段一：价值发现]**
  * **Round 1 发散**: Planner 发送 `Vibe_0` 给 [专家2-技术, 专家7-合规]。专家2极度看多（技术奇点）；专家7极度看空（面临退市风险）。
  * **Round 1 收敛**: Talent 提取冲突：“技术奇点” VS “合规生命线”。提出新假设：“时间延迟创造洼地，真正的风险不在于 FDA，而在于 NLK 的现金流能否撑过漫长的审批周期。”
  * **Round 1 裁决**: Planner 认为“现金流与宏观环境”信息不充分。生成 `Vibe_1` (融入现金流假设)，未达5轮上限，继续价值发现。
  * **Round 2 发散**: Planner 发送 `Vibe_1` 给 [专家1-宏观, 专家4-资金]。专家认为当前高息环境下，一级市场融资困难，但若有军工/DoD 隐性订单则可破局。
  * **Round 2 收敛**: Talent 总结：“纯商业化路径死局，但作为地缘科技博弈资产，其底层流动性无虞。”
  * **Round 2 裁决**: Planner 认定逻辑闭环（信息充分），推进至下一阶段。

* **[阶段二：标的锁定]**
  * **Round 3 发散**: Planner 宣告进入标的锁定。选取 [专家8-商业模式, 专家10-第二层思维]。专家指出 NLK 估值过高且无流动性，建议锁定其核心“柔性电极材料”的独家供应商 $XYZ 材料 (XYZ.US)$，以及提供 BCI 动物实验外包的 $CRO 医药 (CRO.US)$。
  * **Round 3 收敛**: Talent 评估认为 $XYZ 材料$ 更符合原始 Vibe 中“硬科技突破”的偏见，而 $CRO 医药$ 偏离了主线。
  * **Round 3 裁决**: Planner 认定标的聚焦成功，锁定 $XYZ 材料$，推进至下一阶段。

* **[阶段三：数据验证]**
  * **Round 4 发散**: Planner 宣告进入数据验证，发送锁定标的给 [专家5-深度价值, 专家6-黑天鹅]。专家进行逻辑推导：XYZ 材料 70% 营收来自消费电子，BCI 业务占比不足 5%，即使 NLK 爆发，对 XYZ 利润表增厚不超过 2%。黑天鹅风险在于大客户砍单。
  * **Round 4 收敛**: Talent 切换为审计视角，指出：“专家计算无误，XYZ 材料存在严重的‘题材纯度不足’问题，盈亏比极差。”
  * **Round 4 裁决**: Planner 认定验证完成，生成最终报告。

* **[最终输出 -> END]**
  * 输出综合报告：保留对 BCI 赛道的 Vibe 认可，但**否决**当前维度的直接投资。结论：NLK 胜率低，上游供应链纯度不够。建议等待产业链出现纯粹的“铲子股”。（全程在 CLI 中可展开查看每次并发的完整 Think 过程）。

## 4. 交付要求
* 核心代码基于 LangGraph 框架构建 FSM，处理好节点的 Fan-out/Fan-in 状态更新。
* 使用 `uv` 管理 Python 依赖包，保证一键部署体验。
* 优先考虑使用 DeepSeek 作为远端 LLM API 提供商。将模型能力分级：Talent / Expert_Swarm 内部深思应使用 Reasoner 模型；Planner 路由判断、固定格式抽取等快速交互场景使用 Chat 模型。
* 预留良好的前后端分离接口，方便未来与 TypeScript 前端网页融合。
* 保证 CLI 工具的交互性：人工可随时打断 Agent 工作流；思考过程中 CLI 显示哪些专家正在思考，结束后展示格式化摘要，详细思考过程可通过交互按需读取。
* 架构需具备高扩展性，允许未来将 Expert_Swarm 中的单一专家升级为子工作流。
* 提供模式切换能力，让用户可以自由切换“价值发现”、“标的锁定”、“逻辑验证”三个模式，也可以使用1+2，1+2+3等混合模式。
